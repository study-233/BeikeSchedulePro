# 多课表管理验收

## 数据与升级

- Room 版本由 5 升至 6。`MIGRATE_5_6` 将旧课程和节次归入 ID 为 1 的“默认课表”，保留原课程 ID、隐藏状态和其他业务表。
- Repository 首次访问时读取旧 DataStore 学期配置，在 Room 事务中写入默认课表并设置初始化完成标记。读取或写入失败可以重试；完成后不再使用旧学期键，旧键暂保留以避免跨存储清理中断。
- 课表名称独立于学期名称。当前课表、课程、节次和校历通过 Room 事务关系查询形成完整快照；课程写入和草稿保存限定明确课表 ID。
- 本次源码编辑没有执行构建、测试、Lint、schema 生成或设备操作。版本 6 schema 必须由开发者使用已有工具链生成并核对，不手写 identity hash。

## 开发者检查

在仓库根目录使用 wrapper。macOS/Linux 可运行：

```sh
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest :app:lintDebug :app:minifyReleaseWithR8
```

Windows PowerShell 将 `./gradlew` 替换为 `.\gradlew.bat`。首次构建后检查并纳入 `app/schemas/com.caeamer.beikeschedule.data.local.AppDatabase/6.json`。Android 测试 assets 已包含 `app/schemas`；新增 `room-testing` 与项目现有 Room 使用相同版本，没有升级运行时依赖。

设备可用时由开发者运行 `:app:connectedDebugAndroidTest`，重点检查：

- `ScheduleMigrationTest`：5 → 6 schema 校验、旧课程 ID/隐藏状态/节次及旧日程保留。
- `ScheduleRepositoryTest`：初始化失败重试、同名课程隔离、导入隐藏状态与手动课程保留、清空/删除、旧草稿拒绝保存、事务回滚和连续切换。
- `ScheduleManagementUiTest`、`ImportTargetUiTest`：名称校验、取消删除、清空、切换、重命名失败保留输入、状态恢复、目标选择及跨学期确认。
- `ImportCommitTest`：重复提交保护、失败恢复完整预览和重试。
- JVM `ScheduleManagementTest` 与现有 `ReminderSchedulingTest`：提醒身份失效与普通重排保留到点未投递提醒。

## 手动验收

1. 覆盖安装前准备导入、手动、隐藏和无固定时间课程，以及已设置的学期日期。升级后确认全部进入默认课表，校历、节次、隐藏状态及成绩、考试、历史日程仍保留。
2. 从课表更多菜单、课表设置和“我的”进入管理；新建空课表后自动切换。默认新名称自动追加序号，名称去除首尾空白后不能空白或重名。
3. 给 A/B 两份课表添加同名课程及不同校历、节次时间。来回切换，只显示所属课表的课程和日期；顶部名称切换、当前周定位和重启后的当前课表恢复正确。背景、字号和显示开关共用。
4. 重命名课表后学期名称不变；修改学期设置只影响当前课表。取消或返回不保存未确认草稿。
5. 清空 A：含隐藏、手动和无固定时间的课程全部删除，名称、校历和节次保留，B 完整保留。取消确认不产生修改。
6. 删除非当前课表不改变当前选择；删除当前课表转到最早创建的剩余课表；删除最后一份后得到空白默认课表，不自动重新出现示例课程。
7. 教务导入默认新建；选择更新必须指定课表。更新后保留目标的自定义名称、手动课程和教务课程隐藏状态，替换其教务课程、校历和节次并清除其中的示例课程。其他课表不变。跨学期确认可取消。
8. 导入预览旋转屏幕后保留名称、目标和确认选择；连点确认只提交一次。模拟保存失败后预览和输入仍在，重试成功后退出，不能再次提交已成功的导入。
9. 添加多个桌面小组件，切换 A/B 后全部跟随最终选中的课表。打开小组件定位该课表当前教学周。
10. 开启上课提醒，切换课表、清空或删除当前课表后确认旧提醒取消；系统迟到的旧广播不应弹通知。快速 A→B→A 后只使用最后一次有效版本。普通每日重排仍保留已到点但尚未投递的提醒，考试提醒不受影响。

课表写入与系统闹钟/小组件刷新不属于同一系统事务：课表先完整落库，界面观察者请求刷新；开机、重新打开应用及每日脉冲会重新排期。通知接收端校验课表 ID 与版本，阻止过期课表提醒。
