# 调休配置维护与验收

## 配置来源

维护文件为仓库根目录的 `data/calendar-adjustments.json`。支持此功能的 App 固定读取：

`https://raw.githubusercontent.com/study-233/BeikeSchedulePro/main/data/calendar-adjustments.json`

首次使用需安装支持调休的新版 App，并将 JSON 发布到仓库 `main` 分支。之后只更新 JSON，无需重新发布 APK。本次源码修改不会自动提交或发布文件；远端文件尚未发布时 App 会显示获取失败，并继续使用原课表或已有有效缓存。

数据由项目维护者提供，依据已经确认的学校安排维护，不根据国家节假日或校历颜色自动推算。App 不解析学校通知，也不上传课表、账号或登录凭证。

## 字段与规则

| 字段 | 含义 |
| --- | --- |
| `schemaVersion` | 当前固定为 `1`，改变结构需升级客户端支持 |
| `revision` | 正整数，每次发布内容变化必须递增 |
| `semesters` | 完整学期配置列表，学期由 `xn` 和 `xq` 精确匹配 |
| `xn` / `xq` | 学年如 `2026-2027`；学期代码沿用教务数据 |
| `suspendedDates` | 取消这些日期的常规教务课程，日期格式为 `yyyy-MM-dd` |
| `extraClasses[].date` | 实际补课日期 |
| `extraClasses[].sourceDate` | 原课程日期，用于确定教学周、星期和周次位图 |
| `extraClasses[].note` | 可选说明，最多200字，显示在课程详情和设置页 |

补课追加到实际日期，保留当天原有课程；手动和示例课程不受调休影响。若要替换全天教务课程，可同时将该日放入 `suspendedDates` 并为该日配置补课。停课规则仅取消常规课程，不取消明确追加的补课。

来源课程从未应用调休的原课表读取，不递归应用其他补课规则。来源日停课不会使补课消失。同一课程行在同一实际日期、同一节次重复命中时只显示、提醒一次；不同课程的时间冲突仍并排展示。隐藏课程不显示、不提醒。

来源日期按当前课表的校历解析；有官方校历时优先使用官方教学周。任何来源日无法定位时，整组学期规则暂停应用，并在课表和设置页显示原因。请先同步正确的学期校历，不要仅按连续自然周猜测单双周。

## 日常更新

1. 在对应学期增加或修改日期规则，并递增顶层 `revision`。保留历史学期，避免更新时意外撤销历史安排。
2. 撤销补课时删除相应 `extraClasses` 条目；原日期恢复上课时同时移除对应 `suspendedDates`。仍须递增版本。
3. 同一学期不重复，停课日期不重复，补课的日期组合不重复，实际日期不能等于来源日期。一个实际日期可以补多个不同日期的课程。
4. 使用下面的测试检查格式与行为，再将文件发布到 `main`。字段顺序、空白和规则顺序变化不算内容变更；同版本的语义变化会被拒绝。
5. 在 App“课表设置 → 学期与校历 → 查看调休安排”点击“立即刷新”，核对版本、检查时间及实际课程。

App 进入前台时每24小时最多自动检查一次，失败也计入间隔，不新增后台网络轮询。手动刷新绕过间隔；同时进行的检查共用一个请求。远端文件限256 KiB，连接和读取各有10秒超时。

有效配置缓存在本地，离线、HTTP错误、损坏文件、不支持的格式、版本回退或同版本内容变化均不覆盖缓存。新版本的有效空列表会明确撤销原规则。重新导入课表不会清除调休配置。

## 验证交接

本功能涉及 Room 9→10 迁移，新增独立配置表，原课程、成绩、考试表保持不变。请由开发者构建生成并审查 `app/schemas/com.caeamer.beikeschedule.data.local.AppDatabase/10.json`；不要手工编造 Room identity hash。

源码编辑任务不执行下列检查，由开发者使用仓库 wrapper 运行：

- Windows PowerShell：`.\gradlew.bat testDebugUnitTest lintDebug assembleDebug minifyReleaseWithR8`。
- macOS/Linux：`./gradlew testDebugUnitTest lintDebug assembleDebug minifyReleaseWithR8`。
- 在可用设备或模拟器上运行 `CalendarAdjustmentStorageTest`，覆盖9→10、5→10迁移、缓存、并发刷新、更新与撤销；继续运行既有课表存储和迁移测试。
- `CalendarAdjustmentsTest` 会读取实际维护文件、检查已确认的2026年规则，并覆盖跨周计算、小组件、下一节课与提醒。未来修改已确认安排时同步更新对应断言。

人工验收：

1. 9月20日显示第4周周二课程，保留当天原有课程；10月10日显示第4周周三课程；10月6日、7日不再显示常规教务课，也不显示其淡化占位。
2. 打开“隐藏周末”，上述补课周仍展示七天；普通无补课周继续展示五天。补课标记优先于放假背景，今天仍高亮。
3. 补课卡片显示“补课”，详情显示实际日期、来源日期和备注；同名手动课程保持自己的身份和日期。
4. 验证补课日原课程与补课冲突时并排；隐藏课程后，课表、小组件和提醒一致变化。
5. 使用测试配置将补课放入校历跳过的假期周：应出现带日期范围的“调休周”，原教学周编号不变；回到今天和小组件跳转落在实际日期，额外页面不支持空白格长按添加。
6. 更新或撤销调休后核对旧闹钟取消、新闹钟按实际日期排期；用固定日期的单元测试验证历史9月20日，不要求修改设备系统时间。
7. 断网后重启仍使用缓存；错误文件和低版本不清空安排；不同学期课表不误用规则；重新导入后不重复补课。

调休配置属于补充排期，不会改写教务课程位图，也不会修改考试和成绩。
